## 구현된 항목
- 브랜드 전용 반응형 고객 랜딩페이지
- 검증 가능한 소재지 안내·외부 지도 링크 및 주소 복사

- Node 내장 테스트 러너 및 GitHub Actions CI

## 실서비스 전 필수 미해결 사항
1. 법인등기·건물 소유권·임대 대상 층/호실·용도 및 관련 조건 확인
2. 사업자등록 가능 업종·세무서/지자체 실사 요건, 사용 계약의 적법성 확인
3. 법인 사업자등록번호·대표자·통신판매업 신고 필요 여부·연락처 확정
4. 임대차계약서와 청약철회/환불/민원/개인정보 처리방침 법률검토
5. 회원인증·법인 서류·개인정보 암호화·권한 제어·감사로그·백업 구축
6. PG 가맹점 계약/테스트 상점ID·키 발급, 표준 결제 요청 서명·원장·정산 검증
7. 결제의 진실 원천은 서버-서버 승인/조회 API로 확인, 브라우저 완료 화면만 믿지 않기
8. 웹훅 서명·중복 처리/재시도·부분 환불·가상계좌 입금 통지 검증
9. 전자서명·전자문서 발급 및 재발급, 동의·문서 버전·증빙 보관
10. 운영용 배포 계정/도메인/DNS/HTTPS, CS 대응과 장애 복구 테스트

## 헥토파이낸셜 준비
- 공식 기술문서: https://developers.hectofinancial.co.kr/docs/pg
- 상점ID·보안키·서버 인증정보는 배포 환경의 비밀 변수로 저장. Git 커밋 금지
- `HECTO_MERCHANT_ID`, `HECTO_HASH_KEY`, `HECTO_ENV` 등의 환경 변수 이름은 자체 설계이며 실제 공식 SDK 필드와 매핑 필요
- 계약 형태(직연동/대행), 결제수단, 정기결제 지원범위는 가맹점 승인 후 확정
- 현재 SDK 호출이나 실제 카드/계좌 정보를 수집하는 화면을 구현하지 않았음

## 운영 아키텍처 확장
- Frontend: 반응형 UI
- Backend: 서버가 가격 및 주문을 권위 있게 관리
- DB: PostgreSQL (지점, 계약자, 적합성 심사, 계약, 청구, 결제, 웹훅, 문서, 우편물, 감사로그)
- Object storage: 전자계약서와 우편 이미지의 접근제어 저장
- Notifications: 문자/이메일 발송 어댑터
- Admin: 운영자 MFA 및 최소권한 접근
- Maps: 정식 키 발급 및 약관 확인 후 지도/로드뷰/주소 API 사용

## 검수·병합 규칙
PR 단위 검토. 테스트 통과와 무관하게 '실서비스'로 인정하지 않음. 사용자 승인 없이는 PG 운영키 등록·상용 결제·고객정보 수집 금지.
