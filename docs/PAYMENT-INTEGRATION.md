# Hecto payment integration — sandbox architecture
Official source https://developers.hectofinancial.co.kr/docs/pg (reviewed 2026-11-24). Use hosted SDK SETTLE_PG.pay, test origins tbnpg.settlebank.co.kr and tbgw.settlebank.co.kr. No SDK invocation or real provider query implemented. The ledger is an in-memory test model, not an endpoint; its verifier is an injected test dependency. Never expose it to browser input as a trusted verifier.
Production prerequisites: authenticate customer, derive amount from persisted signed contract and approved quote, enforce order ownership, implement method-specific Hecto encoding, signing/encryption and authoritative transaction query, configure HTTPS notification and return URLs, validate merchant identity and currency, persist events and state in a single PostgreSQL transaction with locks and uniqueness, handle retry/reconciliation, protect logs and secrets. Browser return is not approval. Virtual account issuance is not deposit. Full refund only in initial model; partial refund and billing disabled. Billing requires separate merchant approval and revocable consent. Credentials must be server-side environment variables, never repository or chat. Existing public checkout APIs remain blocked. No real network transaction or funds moved.
